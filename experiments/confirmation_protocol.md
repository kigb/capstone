# 30 道新题确认实验：冻结协议

本轮检验冻结的 Behavior-k 是否优于均匀处理 Degree 并列的策略。协议在新题推理前固定；[机器配置](../results/netsafe_confirmation_qwen8b/protocol.json) 的排序键 JSON SHA-256 为 `4a81a1c187ec06bbd9d08603c7cf7b760e8f1de0a75fd1a152aaa363efb90dbe`。

## 数据和沿用配置

保持原来的 Qwen3-8B revision、non-thinking、BF16、greedy、batch size 32、512-token 上限、8 节点图、4 轮讨论、固定 warning 和 k=2 预算。源位置仍为 0、3、6，攻击源不计分也不在保护候选中；每个保护集合均配对 clean/attack。

Behavior 原样沿用此前 10 道开发题 × 3 个攻击位置得到的冻结模型，保护 `{2,4}`，本轮不重新估计或调参。准备及分析阶段仅重新拟合旧开发日志以核验模型一致。此前 10 道测试题的结果不进入评分拟合；它们用于发现并列对照不足，因此此前试验是探索性阶段。

数据源包含 112 道有效标签题。排除之前六份问题文件中出现过的全部 20 个不同题目 ID，从剩余 92 题中以 seed 20261120 抽取 30 题；错误目标以 seed 20261121 固定。按抽样顺序循环分配源位置 0、3、6，正好每个源位置 10 题。本轮仍只检验未见题目，不声称检验未见图或未见攻击位置。

冻结的 [behavior_model.json](../results/netsafe_confirmation_qwen8b/behavior_model.json) 是旧模型文件的逐字节副本。新协议、模型副本和全部测试条件的哈希及冻结时间另存于 [freeze.json](../results/netsafe_confirmation_qwen8b/freeze.json)。任何测试生成必须晚于该时间。

## 策略及并列对照

保留无 warning、全部普通节点保护、Degree-k（按 ID 处理并列）、Betweenness-k、Behavior-k 和三个 Random-k 集合。Random 的集合与此前相同，仍在每道题内先平均。

新增 Degree-uniform：枚举每个攻击位置下所有度数之和最大的合法 k=2 子集，再对这些子集的结果均匀平均。这等价于对该图的 Degree 截断处均匀随机处理并列后的期望结果，不依赖有限随机抽样。

| 攻击源 | Degree-uniform 枚举的保护集合 |
| --- | --- |
| 0 | `{1,2}`、`{2,4}`、`{2,6}` |
| 3 | `{1,2}`、`{2,4}`、`{2,6}` |
| 6 | `{1,2}`、`{2,4}` |

Degree-uniform 的计算顺序必须是：**每道题先平均其 2 或 3 个集合，再对 30 道题等权平均**。直接汇总全部集合的分子分母会使攻击源 0、3 的题目比源 6 获得更多权重，因此不作为主要估计。

`{1,2}` 同时是 Degree 与一个枚举集合，`{2,4}` 同时是 Behavior 与一个枚举集合；部分 Random 集合也与其他策略相同。保留各策略别名以便审计，所有相同消息只进行一次 greedy 生成。共 640 条命名轨迹、25,600 个逻辑回答；按题目、攻击条件和实际保护集合去重后为 480 条不同条件轨迹。别名和缓存复用不增加独立样本量。

## 主要比较与分析

唯一主要比较是：**最终第 4 轮、有攻击条件下，Behavior − Degree-uniform 的普通节点目标采纳率差**。负值表示 Behavior 较好。报告点估计及 10,000 次按题目配对 bootstrap 的双侧 95% 百分位区间，bootstrap seed 20261120。先完成全部 30 题，不根据中间结果提前停止或调整配置。

其他指标为次要描述性分析：准确率、clean 表现、无效答案、系统严格多数票（4/7）、曾经采纳率、逐轮结果、源服从率、距攻击源的距离、逐题差值及随机集合变化。次要策略比较不作多重比较校正，不根据结果挑选为主要结论。主要区间估计条件于当前图、冻结评分和攻击设置，不包含重新学习评分或更换网络的不确定性。

为区分正常性能变化与攻击影响，补充每题 attack − clean 增量的策略间差值。普通节点、讨论轮次、随机集合和 Degree 并列集合都不能作为独立题目抽样。样本量为 30，不与此前 10 道探索性测试题合并作为确认结果。

## 运行与留存

本轮只运行新题，无开发推理，也不修改既有结果。原有运行后端和交互代码直接复用，记录源文件哈希。每轮写检查点，生成结果逐 batch 落盘，中断后可使用同一输出目录恢复。完成后将原始 JSONL 按字节无损压缩为 `.jsonl.gz`，保留解压内容的 SHA-256；分析脚本直接读取压缩记录。模型权重和虚拟环境不提交。

准备和运行：

```bash
python scripts/run_placement_confirmation.py --prepare-only
python -u scripts/run_placement_confirmation.py
.analysis-venv/bin/python scripts/analyze_placement_confirmation.py
```

成本预估为 12–16 小时本地推理，基于上一轮吞吐推算，实际取决于输出长度和缓存复用。实验未保证具有检测当前点估计差异的统计功效；无差异或反向结果同样完整报告。
